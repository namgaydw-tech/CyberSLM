# CyberSLM-35M → verification → Qwen bridge

This is an optional integration for the existing CyberSLM repository. The original Streamlit
modes, checkpoints, GGUFs, and model files remain unchanged. It creates a genuinely sequential
model handoff and shows intermediate results in a separate Streamlit page.

## Where the models communicate

**`src/cyberslm/two_model_bridge.py`, inside `run_bridge()`**:

1. `get_scratch_manager().infer(prompt)` invokes the scratch-trained
   `cyberslm-35m-structured-byte:latest` Ollama model, then the verified native checkpoint if the
   Ollama path is unavailable.
2. `status, verified = check_question(facts, question)` computes an independent reference for a **narrow supported question set**. Unsupported questions are explicitly *not verified*.
3. `evidence_packet = { ... "scratch_neural_prediction_UNVERIFIED": prediction, "independent_reference_if_supported": verified, ... }` creates the model-to-model data packet.
4. `response = conversation_fn(bridge_prompt, [], model=..., provider=..., ...)` passes that packet
   through the Qwen runtime manager: Ollama first, LM Studio second, and a grounded degraded result
   if neither is available.
5. The page displays the **scratch output, independent check, and Qwen explanation** separately. Mismatches are visible rather than disguised.

## Install without overwriting the existing working application

In PowerShell at the project root:

```powershell
.\.venv\Scripts\Activate.ps1
$env:PYTHONPATH = (Join-Path (Get-Location) "src")
python -m unittest discover -s tests -p "test_two_model_bridge.py" -v
.\presentation\Start-CyberSLM-Assistant.ps1
```

Streamlit automatically discovers extra pages under `app/pages/`. Open **CyberSLM Qwen Bridge**
in the navigation. Supported questions invoke the scratch model and independent verifier. Qwen is
optional; if it is down, the scratch result and verification remain visible.

**Prerequisites:** Prefer registering the scratch GGUF as
`cyberslm-35m-structured-byte:latest`; the identity-checked native checkpoint is the fallback. Qwen
may be available through Ollama as `qwen2.5:1.5b-instruct-q4_K_M` or LM Studio as
`cyberslm-practical`. The RAG index must exist before retrieval is enabled.

This is intended for **local deployment**; Streamlit Community Cloud has no direct access to your laptop's `127.0.0.1` services.

### Example question

The default fictional three-event dataset supports `count unique event types` → independent verified reference `2`. Your neural model may agree or disagree. It is not expected to generalize correctly to every event count: the original structured neural frozen exact match was **34.38%**, not 100%.

The bridge only verifies exact event-type counts, unique types, a unique most-frequent type, and the narrow unsupported-verdict question. The `NO` response means **a confirmed attack is not established by event counts**, not that attacks are impossible or absent. Everything else remains unsupported by the deterministic checker.

### Verification boundaries

- The unit tests use **mock models** to verify call order, handoff, and explicit disagreement handling; they do *not* constitute live endpoint testing.
- Live Windows verification on 20 November 2026 confirmed 3/3 selected native-versus-Ollama
  scratch outputs and Qwen Ollama-to-LM-Studio failover. This remains a bounded demonstration.
- The scratch-model output is always attributed and unverified. Qwen's explanation is generated by a separate pretrained model, not by the 35M model.
- This bridge does not mean the 35M model trained Qwen, or that Qwen and the 35M model were jointly fine-tuned.
